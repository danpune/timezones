Inside Time Zones

The whole site is one web page kept on GitHub. There is no server doing work in the background, no database and no app store. Your phone downloads the page and does every calculation itself. Here is how it all comes together.

The big picture

Think of it like a recipe. GitHub keeps the recipe, GitHub Pages hands out copies, and your phone does the cooking.

Where it actually runs

Your phone's browser

What time is it there?
Answered by the time zone database built into your phone, the one the Clock app uses. Daylight saving rules come with it.
Is the sun up?
An astronomy formula turns each city's latitude and longitude into the sun's height for every hour. That gives sunrise, sunset and the sky colours.
Which cities did I pick?
Saved on this device. The link carries them too, like #Austin,London.
No signal?
The offline helper keeps a copy of the page, so it still opens.
Asks outside, when online
  • Open-Meteo for the weather, all cities in one request
  • hits.sh for the visit counter
  • Cloudflare for anonymous visit statistics, no cookies

The key ideaGitHub stores and serves files. Everything except the weather and the visit counts is worked out on your own phone.

One tap, start to finish

What happens in the second or so after someone opens the link.

  1. You open the linkYour phone

    The browser asks GitHub Pages for the page at danpune.github.io/timezones.

  2. The page arrivesGitHub Pages

    One file, index.html, about 110 KB. That's smaller than most photos, and it holds the whole app.

  3. It decides which cities to showYour phone

    Cities in the link come first. Otherwise, the ones you saved last time. Otherwise, Austin, San Francisco, New York, Mumbai and London, plus your own time zone if none of those match it.

  4. It asks the phone for each city's timeYour phone

    "What time is it in America/Chicago?" The phone's time zone database answers, with daylight saving already applied.

  5. It works out the sun and paints the stripsYour phone

    The sun's height for all 24 hours of each city's day, turned into colours from night blue through sunrise orange to day blue.

  6. It fetches the weatherOpen-Meteo

    One request covers every city. With no internet, each card keeps its sun or moon symbol instead.

  7. It saves a copy for next timeYour phone

    The offline helper stores the page, the city list and the icons, so the site opens even without a connection.

  8. It keeps the clocks movingYour phone

    Every 5 seconds it checks the time and redraws when the minute changes. Nobody needs to refresh.

The technical design

The same system, end to end, the way an engineer would draw it: how it is built and published, and what runs on the visitor’s device.

Always happens Only when online GitHub and the developer’s Mac Visitor’s device Internet services
One file, no build
HTML, CSS and JavaScript all live in index.html. No framework and no dependencies; any plain web server can run it.
State in the link
The address holds the cities, base city and any planned time, so a copied link opens the same view. Local storage keeps it between visits.
Time
Intl.DateTimeFormat reads the device’s IANA time zone database. Times that fall inside a daylight-saving jump are resolved by bisection, so the slider never runs backwards.
Sun
NOAA’s solar position formula gives the sun’s height. Sunrise and sunset use −0.833° to allow for refraction and the sun’s disc, cached per city per day.
Offline and loading
The service worker serves the page network-first and files cache-first. The offline helper saves the city list on the first visit; search reads it when you first type. Flags load only when shown, weather in one call.
Safety
Text from a link, a rename or storage is escaped before it reaches the page, and map positions in links are range-checked.

How a change goes live

Updating the site is saving a file and sending it to GitHub. There is no install and nothing to restart.

  1. EditChange index.html
    →
  2. CommitSave it with a note
    →
  3. PushSend it to GitHub
    →
  4. PublishPages updates, about a minute
    →
  5. RefreshPhones get it on next open

Each version is stamped at the bottom of the page, for example build 2026.09.12-k. When a phone opens the site and finds a newer version, the page reloads itself once to switch over.
